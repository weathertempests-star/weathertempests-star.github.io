收到一段 AI 協助撰寫的程式時，可以先問一個具體問題：如果它算錯了，我會從哪裡看出來？

有些錯誤會讓程式停下來，另一些則會留下格式正常、數值不對的輸出。要分辨後者，需要一個獨立於程式的預期。本篇使用自行構造的教學程式，演練如何從手算答案開始驗收。

例子選擇梯度下降（Gradient Descent）。它只有幾行程式，卻能同時展示方向、步長與邊界條件如何影響結果。整個實驗可在本機重做，不需要呼叫模型。

## 先挑一個知道答案的問題

我們要找函數 $f(x)=(x-3)^2$ 的最小值。平方不會小於零，當 $x=3$ 時剛好等於零，因此答案已知。

梯度下降沿著負梯度方向更新位置。在這個一維函數中，導數為 $f'(x)=2(x-3)$，更新式是：

$$
x_{t+1}=x_t-\eta\,2(x_t-3)
$$

$\eta$ 是這次選用的正步長。一般方法可參考 Boyd 與 Vandenberghe 的《Convex Optimization》第 9.3 節；以下的具體函數、數值與檢查則由這個例子推導。[教材原文](https://web.stanford.edu/~boyd/cvxbook/bv_cvxbook.pdf)

先取 $x_0=0$、$\eta=0.1$，手算一次得到 $x_1=0-0.1\times(-6)=0.6$。這是第一個驗收點：若程式把減號寫反，第一次就會得到不同結果，無須等到最後才猜哪裡出了問題。

## 用誤差寫出第二份答案

只看最後是否接近 $3$，還不足以說明過程。我們把到最小點的帶正負號距離記作 $e_t=x_t-3$，代入更新式：

$$
e_{t+1}=(1-2\eta)e_t
\qquad\Longrightarrow\qquad
x_t=3+(x_0-3)(1-2\eta)^t
$$

右邊可以直接計算第 $t$ 步，不需要重跑迴圈。它提供了另一種核對方法：將程式逐步算出的值，和推導出的值逐一比較。

這個誤差式也解釋了步長的影響。當 $0<\eta<1$ 時，係數的絕對值小於一，誤差會趨近零；係數若為負，每次更新就會換到最小點的另一側。**這個範圍來自目前的二次函數，不能直接當作所有最佳化問題的設定。**

## 五種步長，五種行為

固定從 $0$ 出發，做八次更新，可以觀察到：

| 步長 $\eta$ | 第八步 $x_8$ | 與 $3$ 的距離 | 行為                   |
| ----------- | -----------: | ------------: | ---------------------- |
| 0.1         |   2.49668352 |    0.50331648 | 從同一側逐步接近       |
| 0.5         |   3.00000000 |    0.00000000 | 第一步就到達最小點     |
| 0.75        |   2.98828125 |    0.01171875 | 在兩側交替接近         |
| 1.0         |   0.00000000 |    3.00000000 | 在 $0$ 與 $6$ 之間往返 |
| 1.1         |  -9.89945088 |   12.89945088 | 距離逐步放大           |

步長 $1$ 是很有用的邊界例子：程式可以正常完成，最後的數字也很整齊，卻沒有接近答案。若驗收只要求「執行成功並輸出一個數字」，這種結果就會被放過。

反過來說，也要避免寫出會拒絕正確結果的條件。例如步長 $0.75$ 的第一步是 $4.5$，已經跨過最小點，但後續的距離仍會縮小。「所有中間值都必須小於三」就不適合當作驗收規則。測試的預期同樣需要理由；這裡可以回到誤差係數，判斷應該觀察位置的正負、距離的大小，還是最終是否收斂。

## 把預期變成可執行的檢查

將下面的程式存成 `gradient_check.py`，以一般 Python 3 執行 `python3 gradient_check.py`。它只使用標準函式庫。

```python
from math import isclose


def trajectory(rate, steps=8, x=0.0):
    history = [x]
    for _ in range(steps):
        x = x - rate * 2 * (x - 3)
        history.append(x)
    return history


# 先對照手算的一步；零次更新則應保留起點。
assert isclose(trajectory(0.1, steps=1)[-1], 0.6, abs_tol=1e-12)
assert trajectory(0.1, steps=0) == [0.0]

rates = (0.1, 0.5, 0.75, 1.0, 1.1)
print(" rate            x8       distance")

for rate in rates:
    history = trajectory(rate)
    assert len(history) == 9  # 起點加上八次更新。

    # 用推導式核對每一步，不只核對最終輸出。
    for step, actual in enumerate(history):
        expected = 3.0 - 3.0 * (1.0 - 2.0 * rate) ** step
        assert isclose(actual, expected, rel_tol=1e-12, abs_tol=1e-12)

    final = history[-1]
    print(f"{rate:5.2f}  {final:12.8f}  {abs(final - 3):12.8f}")

print("All checks passed.")
```

實際執行輸出如下，與前面的數值表一致：

```text
 rate            x8       distance
 0.10    2.49668352    0.50331648
 0.50    3.00000000    0.00000000
 0.75    2.98828125    0.01171875
 1.00    0.00000000    3.00000000
 1.10   -9.89945088   12.89945088
All checks passed.
```

`isclose` 使用容許誤差比較浮點數；這裡的相對與絕對容差，是為本例數值尺度選用的設定。不同的精度要求需要重新決定，不能只把容差調大到測試通過。[Python 官方說明](https://docs.python.org/3/library/math.html#math.isclose)

## 試著讓檢查抓到一個錯誤

還可以做一次很小的反向檢查：暫時把迴圈中的更新方向改成加號，其餘程式與預期保持原樣。

```python
x = x + rate * 2 * (x - 3)
```

從 $0$ 出發、步長為 $0.1$ 時，這一行會得到 $-0.6$。整份程式會在第一個手算斷言處停止，回報 `AssertionError`。恢復原本的減號後，再跑一次就會通過。這兩種情況都已實際執行核對。

這個嘗試能確認目前的檢查會拒絕一種具體錯誤。如果同時把預期也改成程式剛算出的值，就失去了核對的意義。手算、推導與執行結果之所以分開保留，是為了讓其中一份出錯時，還有另一份可以追問。

## 通過之後，說清楚驗過哪裡

這次可以說：固定函數與起點下，程式在五種步長、八次更新中的數值，與推導式相符；另外也核對了手算第一步與零次更新。

這些檢查沒有測過其他函數、大量迭代、非有限數值或所有可能的輸入。若要把教學程式放進實際工具，還需要依用途補上輸入驗證、停止條件與新的測試。先把已驗證的範圍說準，後續才知道要擴充哪裡。

回到 AI 協作，可以把公式、手算結果、程式與實際輸出一起交回下一輪修改。發現不符時，指出第一個偏離預期的步驟，比只說「結果怪怪的」更容易描述問題。
