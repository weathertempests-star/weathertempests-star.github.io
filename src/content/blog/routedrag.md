查一份年度報告的出版日期，翻到封面通常就夠了。  
若要解釋營收變化，才可能需要對照好幾頁表格、附註與圖表。  
兩個問題都交給同一套繁複調查流程，前者會白費工夫；反過來，只准查一次資料，後者又容易漏掉關鍵線索。

[RouteDRAG](https://arxiv.org/abs/2610.36444v1)研究的正是這種分寸。  
它讓 AI 文件問答系統學會兩個判斷：這一題是否值得啟動能反覆查找的代理程式，以及開始查找之後，下一步是否仍有幫助。  
研究的出發點很樸素：忙得更久，不代表答得更好。

## 找到更多資料，也可能被帶偏

許多文件問答系統使用 RAG，也就是先檢索相關資料，再讓模型根據資料回答。  
較進階的 Agent 能自行安排步驟，找到一段文字後繼續追查相關圖表，或換個關鍵字再找一次。  
這讓它有機會串起分散的證據，也讓無關資訊更容易混進回答。

作者比較「現在回答」與「多做一次操作再回答」，總共檢查 917 組配對結果。  
其中約 85% 沒有改變答案的對錯，其餘則有改善，也有退步。  
這不表示額外搜尋總是浪費，而是同一種動作，對不同問題、不同閱讀進度，可能有完全不同的價值。

## 先選閱讀方式，再決定要不要繼續

RouteDRAG 為問題安排不同路線。  
如果經過核對的結構化欄位已足以回答，就直接取用；其他簡單問題可以走一般檢索，或由能閱讀圖文的模型直接處理。  
只有預期能從反覆查找中獲益的問題，才交給 Agent 深入搜尋。

負責分流的小模型，學的不是「這題看起來多難」，而是 Agent 相較於較短路線能否答得更好。  
訓練時，同一題會經過不同路線：只有 Agent 答對是正面例子，只有簡單路線答對則是反面例子。  
這樣的比較讓系統有機會辨認出某些表面複雜、實際上不需要多查的問題。

進入 Agent 路線之後，另一個控制器會根據已取得的資料、來源位置與操作紀錄，評估接下來的動作。  
語言模型仍負責規劃與填寫查詢內容，控制器則在預期改善足夠明顯時調整它的選擇。  
「停止並回答」也是正式選項，不必等到預算用完才收手。

訓練順序也有用意：先改善 Agent 的操作控制，再讓分流模型學習這個更新後的 Agent 有多大幫助。  
否則，分流者可能仍按舊能力分派任務，就像主管不知道同事已經學會了新工具；實際設計見[論文方法章節](https://arxiv.org/html/2610.36444v1#S5)。

## 少做一些，答案反而稍好

研究以 Qwen3-VL-8B 為主要回答模型，在兩套包含文字、表格與圖片的文件問答測試中比較。  
每題都啟動 Agent 時，準確率分別為 74.68% 與 52.52%；RouteDRAG 則為 75.86% 與 53.80%。  
提升約一個百分點，同時回答模型的呼叫次數減少約 15% 至 16%。  
這些是作者的實驗結果，本文沒有重跑模型或文件索引。

改善幅度不算戲劇性，卻回答了一個實際問題：效率與準確度未必永遠互相抵銷。  
省掉帶來干擾的操作，兩者可能一起改善。  
但主要設定仍讓約八成問題使用 Agent，不能把它形容成大多數工作都已由簡單流程取代。

作者也提高啟動門檻，讓只有約一至兩成問題進入 Agent。  
這種較省資源的設定，準確率仍高於完全不用 Agent 的對照組，但低於完整設定。  
因此，系統提供的是幾種取捨，並沒有找出一個在所有條件下都最好的開關。

## 分流的判斷，也會過時

目前證據來自兩套單輪文件問答測試，尚不能代表長時間對話或持續追蹤研究的工作。  
答案主要由固定模型評分，評分者的偏好也可能影響結果。  
換用其他回答模型後，多數比較有改善，但也有個別組合略微退步。

此外，分流與控制器的訓練需要把同一問題、同一狀態交給多條路線試做。  
這些前期成本沒有完整反映在日後少呼叫幾次模型的數字裡。  
文件種類、使用者問題或檢索品質改變後，原本學到的門檻也需要重新檢查。

RouteDRAG 提供的啟發，是把「要不要多做一步」當成需要學習與驗證的能力。  
一個可靠的研究助手，除了找得到資料，也得辨認何時證據已足夠、何時新的線索只會讓問題更混亂。
