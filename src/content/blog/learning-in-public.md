## 為什麼要留下筆記？

閱讀時覺得理解了，隔幾天卻只剩模糊的印象。筆記的價值，不只是保存資訊，更是讓我們看見自己理解到哪裡。

這篇示範文章提供一個簡單的起點：**把每篇筆記當成一個正在發展的問題，而不是必須完美的答案。**

## 用三個問題開始

每次讀完一篇文章，試著回答：

1. 這篇文章想解決什麼問題？
2. 哪一個觀點改變了我的理解？
3. 我還想繼續追問什麼？

> 寫作不是思考結束後的整理。寫下來的過程，本身就是思考。

### 先記錄，再連結

不必一開始就建立複雜的分類。先保留日期、標題和少量標籤，再慢慢把相關筆記連在一起。

![三張相連的筆記卡片，依序為觀察、提問與連結](/images/knowledge-garden.svg)

例如，讀到最佳化的概念時，可以將文章連到[梯度下降研究筆記](/notes/gradient-descent/)，讓抽象概念和具體推導互相補充。

## 一份簡單的寫作模板

新增文章時，可以用這段 Markdown 作為正文的起點：

```markdown
## 今天的問題

用一句話描述想理解的事情。

## 我的理解

用自己的話整理，並附上例子。

## 接下來

列出尚未解答的問題與參考資料。
```

### 建立可回訪的節奏

| 時機     | 可以做的事                 |
| -------- | -------------------------- |
| 閱讀之後 | 留下一段自己的理解         |
| 每週回顧 | 補充例子，連結相關筆記     |
| 發現錯誤 | 修正內容，保留新的思考方向 |

不需要追求每天發文。選擇能持續的節奏，比累積文章數量更有價值。

## 留一點未完成

好的筆記可以是不完整的。清楚記下「我還不知道什麼」，往往就是下次探索的入口。

試著從今天讀到的一個概念開始，寫下三句話。你的知識花園，就有了第一株幼苗。
